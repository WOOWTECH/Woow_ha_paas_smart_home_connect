# Task: DataUpdateCoordinator 與 Sensor Entities

## Description
實作 `coordinator.py`（DataUpdateCoordinator 統一管理狀態輪詢）、`sensor.py`（tunnel_status + tunnel_url）和 `binary_sensor.py`（tunnel_connected）。Coordinator 每 30 秒合併本地 cloudflared 進程狀態和遠端 API 狀態。

## Acceptance Criteria
- [ ] `TunnelCoordinator` 繼承 `DataUpdateCoordinator`，每 30 秒更新
- [ ] `_async_update_data` 同時檢查本地進程 (`is_running()`) + 遠端 API (`get_home_status()`)
- [ ] 合併產生 `TunnelStatusData` (dataclass): `is_connected: bool`, `status: str`, `subdomain_url: str`
- [ ] `binary_sensor.py`: `TunnelConnectedBinarySensor` — `is_on` 對應 `is_connected`
- [ ] `sensor.py`: `TunnelStatusSensor` — native_value 對應 status 文字
- [ ] `sensor.py`: `TunnelUrlSensor` — native_value 對應 subdomain URL
- [ ] 所有 entity 繼承 `CoordinatorEntity`，自動響應 coordinator 資料更新
- [ ] Entity 有正確的 `device_info` 讓它們歸類在同一個 device 下
- [ ] API 呼叫失敗時 coordinator 記錄 error，entity 顯示 `unavailable` 或 `unknown`

## Technical Details

### Coordinator Data 合併邏輯
| 本地進程 | 遠端 API status | → is_connected | → status |
|---------|----------------|---------------|----------|
| running | connected | True | connected |
| running | disconnected | False | error |
| stopped | connected | False | error |
| stopped | disconnected | False | disconnected |
| running | API 失敗 | True | unknown |
| stopped | API 失敗 | False | disconnected |

### Entity 設定
- `device_info`: manufacturer="Woow", model="PaaS Smart Home", name=smart home name
- `unique_id`: `{entry_id}_{entity_type}`
- `entity_category`: `diagnostic` (這些是診斷性質的 entity)

### 檔案
- `coordinator.py`: TunnelCoordinator + TunnelStatusData dataclass
- `sensor.py`: TunnelStatusSensor + TunnelUrlSensor + `async_setup_entry`
- `binary_sensor.py`: TunnelConnectedBinarySensor + `async_setup_entry`
